## Environment / visual verification: WORKS
Display verified: the game runs under Xvfb + Mesa llvmpipe, F12-free: I use `import -window root` and Read the PNG.
- Root in sandbox, apt-get works. Deps: `apt-get install -y xdotool libasound2-dev libgl1-mesa-dev libglu1-mesa-dev libglew-dev libxrandr-dev libxtst-dev libxinerama-dev libpulse-dev libudev-dev libusb-1.0-0-dev libgtk-3-dev libva-dev libssl-dev libxext-dev libxcursor-dev libxi-dev mesa-utils libgl1-mesa-dri x11-utils sox libjack-dev libx11-dev` (xvfb, ffmpeg, imagemagick, ninja, cmake already present).
- **Submodules must be initialised** (Simply Love theme + extern/*): `git submodule update --init --recursive --depth 1`.
- Build: `cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build -j4` (~6 min cold; binary lands at repo root `./itgmania`, git-ignored).
- Run: `tools/visual-lib.sh` (source it) gives `vt_setup`, `vt_start`, `vt_key`, `vt_shot`, `vt_stop`. It creates `Portable.ini` (so Save/Logs/Screenshots live in the repo dir, git-ignored), installs the test song from `tests/songs/QuadTest` (generated by `tools/make-test-song.py`, silent ogg + 5 dance-single charts meters 1/3/6/9/12) into `Songs/QuadGroup/` (songs must be inside a group folder!).
- Software GL is slow (a screen transition ≈ 3-5 s; wheel animation stutters). Wait ~3 s after each key.
- Default keys: P1 arrows (menu) + Return=Start; P2 numpad 4/2/8/6 + KP_Enter=Start. On the SL music wheel Left/Right move the wheel, Return selects/opens a group.
- Menu path to gameplay (2P): Return (join) ×~4 → title→mode→style; KP_Enter joins P2; select group (Return), Right to move onto song, Return to start.
- `tools/visual-test.sh` (the one-shot scripted run) is NOT written yet (stage 5).
- Simply Love (`Themes/Simply Love`) is a **git submodule** pointing at upstream (dd06138, v5.9.0). Stage 4 must either vendor it into this repo (remove submodule, `git add` files) or push to a theme fork; plan: vendor it into the repo at that point.

GameManager.cpp has default keyboard mappings per game (needs P3/P4 defaults: P3 `o p [ ]`, P4 `a s d f`; P1 `q w e r`, P2 `t y u i` are the requested *test* keys; note P1 arrows still needed for menus).
5. **Profiles / memory cards / save format**: ProfileManager (`m_sProfileDir[NUM_PLAYERS]` — local profiles are indexed by player, `ProfileSlot_Player1/2`), MemoryCardManager (2 slots, USB), ScreenSelectProfile, SongManager/Profile stats are per-profile (not per-slot) so on-disk Stats.xml stays compatible. Preferences `DefaultLocalProfileIDP1/P2` are named per player (need `P3/P4`; additive, backward compatible). Machine-profile files unaffected. `PlayerOptions` per player strings in Preferences/“CurrentPlayerOptions” are per-slot additive.
6. **Network/other**: `NetworkSyncManager`, `ScreenNetSelectMusic`, `StepMania Online` protocol is 2-player (leave as 2P; guard), Lights drivers (Minimaid/BlueDot use PLAYER_1/2 for pad lights — leave as is), `DancingCharacters`/`BeginnerHelper` (2P-oriented; disable for 4P), `ScreenSelectCharacter`.
7. **Theme/Lua**: 128 Lua files in Simply Love + _fallback loop PLAYER_1/PLAYER_2 or position by `P1X=SCREEN_CENTER_X-...`; `Scripts/` helpers (`PlayerNumber` strings "PlayerNumber_P1", `ToEnumShortString`, `GetPlayerAF`, `SL.P1/SL.P2`, `SL[pn]`, `SL.Global.ActiveModifiers`). SL ScreenGameplay uses `GAMESTATE:GetNumPlayersEnabled()` and `IsHumanPlayer`, and hardcodes P1/P2 x positions (`WideScale`, `_screen.cx ± 160`). Lua enum binding `PlayerNumber` comes from the C++ enum (EnumHelper) so adding PLAYER_3/4 automatically exposes them.
8. **Save-file format**: Stats.xml / Profile.ini per profile — no player index inside. Preferences.ini gets new keys only. Machine `Static.ini` etc untouched. => backward compatible if default stays 2 players.

Routine/Couples approach (v1.3.0 PRs ~#1216/#1433): they added `StyleType_TwoPlayersSharedSides`, a `m_RoutinePlayer` in StageStats, CombinedLifeMeter reuse, `Style::m_bRoutine`-ish helpers (`GetUsesCenteredArrows`), EditModePlayerManager, and *keep* NUM_PLAYERS=2. They did **not** generalise the player count, so little reuse beyond style/field placement patterns (Style.cpp column offsets, noteskin per-style names, `GameCommand` style-by-name lookup).
